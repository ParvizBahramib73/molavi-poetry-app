# رفع تعارض نصب و به‌روزرسانی Android — بشنو بخوان

## علت تعارض

نسخه‌های آزمایشی قبلی با امضای پیش‌فرض Debug ساخته می‌شدند. GitHub-hosted runnerها موقت‌اند و هر اجرای مستقل ممکن است debug keystore متفاوتی بسازد. Android برای نصب به‌روزرسانی، علاوه بر شناسه بسته، به گواهی امضای یکسان نیاز دارد؛ APK جدید با گواهی متفاوت به‌عنوان package conflict رد می‌شود.

مشکل دوم این بود که `versionCode` در هر build روی `1` ثابت بود. برای به‌روزرسانی، `versionCode` نسخه جدید باید از نسخه نصب‌شده بیشتر باشد.

## راه‌حل دائمی

- APKهای Debug فقط برای اعتبارسنجی CI ساخته می‌شوند و دیگر به‌عنوان فایل نصب/به‌روزرسانی منتشر نمی‌شوند.
- APK قابل نصب و قابل به‌روزرسانی باید از گردش‌کار `Build Signed Android Release` ساخته شود.
- همه نسخه‌های Release باید با همان keystore دائمی مالک برنامه امضا شوند.
- گردش‌کار Release فقط از شاخه `main` ساخته می‌شود.
- `versionName` نسخه انتقالی `1.0.1` است.
- `versionCode` از تعداد commitهای کامل تاریخچه Git روی `main` محاسبه می‌شود؛ بنابراین checkout با `fetch-depth: 0` انجام می‌شود و هر commit جدید روی main عدد بزرگ‌تری تولید می‌کند.
- شناسه بسته ثابت می‌ماند: `com.parvizbahrami.molavi`.

## مهاجرت یک‌باره از APK آزمایشی قبلی

**یک بار حذف نسخه Debug قبلی اجتناب‌ناپذیر است.** کلید خصوصی Debug که روی runner موقت قبلی ساخته شده بود همراه artifact ذخیره نشده و قابل بازیابی نیست. گواهی عمومی داخل APK برای امضای نسخه جدید کافی نیست. بنابراین نمی‌توان APK جدید را با همان امضای قبلی تولید کرد.

مراحل مهاجرت:

1. keystore دائمی Release را روی دستگاه امن خود بسازید و چند نسخه پشتیبان رمزگذاری‌شده و آفلاین نگه دارید.
2. چهار GitHub Actions secret زیر را در `Settings → Secrets and variables → Actions` ثبت کنید:
   - `ANDROID_KEYSTORE_BASE64`
   - `ANDROID_KEYSTORE_PASSWORD`
   - `ANDROID_KEY_ALIAS`
   - `ANDROID_KEY_PASSWORD`
3. گردش‌کار `Build Signed Android Release` را از شاخه `main` اجرا کنید.
4. فقط یک بار نسخه Debug فعلی را از گوشی حذف کنید و سپس `Beshno-Bekhan-Release.apk` امضاشده را نصب کنید.
5. از این پس فقط APKهایی را نصب کنید که با همان keystore دائمی ساخته شده‌اند. آن‌ها بدون حذف برنامه روی نسخه قبلی نصب خواهند شد، به شرط آن‌که `versionCode` افزایش یافته باشد.

## امنیت کلید

- keystore، رمزها یا Base64 آن هرگز نباید در مخزن، Issue، Pull Request یا چت قرار گیرند.
- کلید Release را برای تمام به‌روزرسانی‌های آینده حفظ کنید؛ تغییر کلید امضا، تعارض نصب ایجاد می‌کند.
- APK Debug را برای انتشار عمومی یا بازار استفاده نکنید.
- از دست‌دادن keystore ممکن است امکان انتشار به‌روزرسانی برای نصب‌های موجود را از بین ببرد.

## اعتبارسنجی قبل از انتشار

- [ ] ساخت Release از `main`
- [ ] تأیید `versionName=1.0.1` و `versionCode` بزرگ‌تر از نسخه قبلی
- [ ] تأیید گواهی امضا با `apksigner verify --print-certs`
- [ ] نصب APK روی دستگاهی که نسخه قبلی Release را دارد، بدون uninstall
- [ ] تأیید باقی‌ماندن داده‌های محلی پس از به‌روزرسانی
- [ ] نگهداری SHA-256 و نسخه پشتیبان keystore
